# 로드맵

**각 단계는 "완료 조건"을 만족하기 전까지 다음 단계로 넘어가지 않는다.**
특히 Phase 0과 1은 "이게 재밌는가"에 답하는 단계다. 여기서 답이 아니면 나머지를 만들 이유가 없다.

각 단계의 **"하지 않는 것"** 목록이 일정 목록만큼 중요하다. 범위가 새는 건 대부분 거기서 시작한다.

## Phase 0 — 모래 (1~2일)

> **이 프로젝트가 재밌을지는 여기서 결정된다.** 나머지 전부보다 중요하다.

`tools/sandbox/` — 빌드 도구 없이 브라우저에서 바로 열린다.

```
automaton.js   [SIM] terrain.md §3 의 제안/해소 자동자. 정수 전용
lab.js         [TOOL] 프리셋 · 계측 · 검증 (브라우저와 harness 가 공유)
index.html     [TOOL] 렌더러 + 실시간 튜닝 UI
harness.mjs    헤드리스 검증 — node tools/sandbox/harness.mjs
```

> **한 파일이 아니라 세 파일로 나눴다.** `[SIM]` 을 분리하지 않으면 헤드리스로 물리를 검증할 수 없고,
> 브라우저에서만 돌리면 "눈으로 봐서 그럴듯한" 상태와 "명세대로인" 상태를 구분할 수 없다.
> 실제로 Phase 0 에서 눈으로는 정상이지만 안식각이 55°(기대 45°)인 버그를 하네스가 잡아냈다.
> 빌드 도구는 여전히 없다 — `<script src>` 두 줄이다.

- 재질 5종, 마우스로 파기 / 그리기 / 폭발
- **모든 상수를 실시간 슬라이더로** (`SUBSTEPS`, `SLIDE_CHANCE_*`, `MAX_SETTLE_STEPS`, 폭발 반경, 재질 저항)
- 안식각 실측 — 기둥을 쌓아 무너뜨린 뒤 사면을 최소제곱 회귀로 각도 출력
- 정착 스텝 수 / 벽시계 ms / 순수 sim ms / 이동 셀 누적 / 가동 셀 수
- **결정론 자기검증 5종** — 재현성, 순서 독립성, 우선순위 동점, 활성 행 무결성, 해시 품질

**완료 조건**

측정 가능한 것과 감각으로만 판정하는 것을 나눈다.

*측정으로 판정 (`node tools/sandbox/harness.mjs`)*
- [x] 자기검증 5종 통과 — `layers`/`hills`/`arch`/`collapse` 4개 시나리오
- [x] `SCREE`(규칙 1·2)의 안식각이 45° ± 2° 이고 최대 열간 낙차가 1 이다 → **실측 44.2°**
- [x] `SAND`(규칙 1·2·3)의 안식각이 26.6° ± 2° 이다 → **실측 26.6°**
- [x] 오버행 슬랩이 캔틸레버로 유지되고, 지지 기둥에 1발 맞으면 연결성 검사가 `ROCK` 을
      `SCREE` 로 바꿔 전부 무너진다 → **실측 16,265셀 변환, 2,508스텝에 정착**
- [x] 질량이 보존된다 (격자 밖 유출 제외)
- [x] **최대 무기(반경 80셀, 12,851셀 제거)가 3,008스텝에 정착한다** → `SUBSTEPS = 17` 이면 3초
- [ ] `SUBSTEPS` / `MAX_SETTLE_STEPS` 확정 — 동시 폭발 간격 스윕이 남았다 (`decisions.md` A3)
- [x] `terrain.md` §4의 상수 실제값이 **문서 표에** 기록되었다 (§11 실측표 + `constants.py`)

*감각으로 판정 (브라우저에서 직접)*
- [ ] 흙을 파냈을 때 무너지는 모습이 "어, 이거 재밌네" 소리가 나온다
- [ ] 지층이 드러나는 순간이 시각적 보상으로 느껴진다

> **"대형 붕괴(화면 1/4 규모)가 3초 안에 정착한다"는 조건을 폐기했다.**
> 129,920셀(25.1%) 붕괴는 27,249스텝이 걸린다 — 수렴하기는 하지만 `SUBSTEPS=4` 로 113초다.
> 셀이 스텝당 1칸만 움직이는데 26.6° 로 퍼지려면 밑변이 화면 폭을 넘어 흙이 500셀 넘게
> 줄지어 이동해야 한다. 그리고 **이 규모는 실전에 나오지 않는다** — 가장 큰 무기가
> 12,851셀이라 10배 차이다. 판정 기준을 최대 무기 + 동시 폭발로 바꿨다. `terrain.md` §11.3·§11.6.

**하지 않는 것**
탱크, 포탄, 게임 UI, TypeScript 빌드 설정. 자동자만 본다.

> `server/` 와 `docker-compose.yml` 이 존재하지만 **게임 서버가 아니라 개발 인프라**다 —
> 샌드박스를 URL 로 열고, Redis/PostgreSQL 연결을 확인하고, 상수 사본을 노출한다.
> `talus/sim/` 에 코드를 넣는 것은 여전히 Phase 3 이다. `docs/development.md`

```
tools/prototype/
  sim.js       [SIM] 탄도 · 탱크 · 턴 해결. 정수 전용
  index.html   [TOOL] 렌더러 + 조준 UI + 실시간 튜닝
```

지형 자동자는 `../sandbox/automaton.js` 를 **그대로 재사용한다.** 복사하지 않는다.

- [x] 탱크 2대, 표준탄 1종, 바람
- [x] 조준 3방식 전부 (드래그 / 키보드 / 직접입력)
- [x] 핫시트 방식으로 번갈아 발사
- [x] 탄도 잔상 (지난 12발, 턴마다 옅어진다)
- [x] 절차적 맵 생성 (`lab.js` 의 `hills` + 시드. 정식 명세는 `decisions.md` B1)
- [x] **실시간 튜닝 패널** — `POWER_SCALE`, `GRAVITY`, `WIND_MAX`, `SUBSTEPS`,
      `SLIDE_CHANCE_*`, 정적 게이트/양방향 토글, 스폰 간격
- [x] 최대 사거리와 맵 폭 대비 비율을 상시 표시 (완료 조건을 숫자로 판정한다)

> **float 로 만들라는 허용을 쓰지 않았다.** 자동자는 이미 정수이고 탄도도
> `tools/ballistics-check.mjs` 에서 정수로 검산해 두었으므로, float 로 쓰면 **버릴 코드를
> 새로 쓰는 것**이 된다. 더 중요한 이유: Phase 2 완료 조건이 "Phase 1 과 체감이 동일하다"인데
> float 로 감각을 잡고 정수로 옮기면 그 조건을 확인할 방법이 없다.
> 처음부터 정수로 잡으면 그 위험이 아예 사라진다 — Phase 2 가 그만큼 싸진다.
>
> 교차 검증: 프로토타입과 `ballistics-check.mjs` 의 평지 사거리가 1 px 이내로 일치한다.

**완료 조건**

*측정으로 판정 (패널에 상시 표시된다)*
- [x] **최대 파워 45° 사거리 = 맵 폭의 100% ± 5%** → 실측 1,900 px = **98.9%** (`POWER_SCALE = 624`)
- [x] 턴 흐름이 끝까지 돈다 — 발사 → 비행 → 붕괴 정착 → 재배치·피해 정산 → 다음 턴
- [ ] `WIND_MAX` 확정 — 45° 편차가 사거리의 10~15% 인 값

*감각으로 판정 (직접 30분 쏴봐야 한다)*
- [ ] 30분을 혼자 앉아서 계속 쏘게 된다
- [ ] 바람이 방해가 아니라 변수로 느껴진다
- [ ] 발밑이 무너져 떨어지는 순간이 실제로 긴장된다
- [ ] 지형이 변해서 다음 조준이 달라지는 게 체감된다

> ⚠️ **"적당한 대각선이 화면 절반쯤 날아간다"는 조건을 폐기했다.**
> 사거리가 맵 폭의 절반이면 맵 양끝에 앉은 두 탱크는 **서로 닿지 않는다.**
> 실제로 그렇게 만들었다가 간격 1,280 px vs 사거리 916 px 로 라운드가 끝나지 않는 것을 확인했다.
> `decisions.md` B12 에서 **사거리를 맵 폭에 맞추기로** 확정했고, 목표치를
> `simulation.md` §8.1 에 "맵 폭의 100% ± 5%" 로 다시 적었다.
> 스폰은 맵의 1/6·5/6 (간격 1,280 px)이며 명중에 파워 약 82% 가 필요하다.

**하지 않는 것**
WebGL, 무기 추가, 상점, 서버, 로비.
**이 단계의 목적은 오직 "재밌는가"이며, UI 코드는 버릴 각오로 쓴다.**

> 원래 이 자리에 "아직 전부 `float` 로 만들어도 된다"가 있었다. **쓰지 않았다** — 위 참조.
> `[SIM]` 구획(`sim.js`, `automaton.js`)은 버릴 코드가 아니라 Phase 2 이식 대상이다.
> 버릴 각오로 쓰는 것은 `index.html` 의 렌더러와 UI 뿐이다.

> ⚠️ Phase 1에서 재미가 안 나오면 **여기서 멈추고 기획을 다시 본다.**
> Phase 2 이후는 재미를 만드는 게 아니라 이미 있는 재미를 포장하고 배포하는 작업이다.

## Phase 2 — 정수화와 결정론 (3~4일)

여기서부터 버릴 코드가 아니다. `client/src/sim/`을 제대로 만든다.

```

    trig.ts        tables/trig.bin 조회. 런타임 Math.sin 금지
    terrain.ts     automaton.js 의 정수 이식 (§3~§8)
    ballistics.ts  sim.js 의 정수 이식 (§4~§6)
  tools/check-no-float.mjs   정적 검사 (TS 쪽 test_no_float)
  tests/determinism.mts      결정론 게이트
  tests/cross-sim.mts        Phase 3 대기 (명확히 SKIP 한다)
tools/gen_trig.py            tables/trig.bin 생성기
```

- [x] `tables/trig.bin` 생성·커밋. **Phase 1 런타임 표와 바이트 단위로 동일**하므로
      표로 전환해도 체감이 안 바뀐다 (sha256 고정, 서버·클라 양쪽 테스트가 대조)
- [x] `isqrt` / `floorDiv` 헬퍼. `floorDiv(-7,2) === -4` — JS 의 `(-7/2)|0` 은 -3 이라 못 쓴다
- [x] 남아 있던 float 전부 제거 — 런타임 `Math.sin/cos`, `Math.floor(a/b)`,

- [x] `check-no-float.mjs` 정적 검사. **의도적 위반 5종을 주입해 실제로 잡는지 확인했다**
- [x] **빌드 도구 없이 돌아간다** — `node --experimental-strip-types` 로 `.ts` 를 직접 실행한다.

**상수 정수화 규칙** (`docs/decisions.md` A4)

3. 확정 상수는 **문서 표가 기준**이고 `server/src/talus/constants.py` 가 기계 판독 사본이다
4. 정수화 후 `harness.mjs` 실측을 다시 돌려 각도·정착 스텝이 5% 이내인지 확인한다

Python 포팅, 서버 로직, 렌더링 개선.

## Phase 3 — 서버 미러 (4~6일)

`server/src/talus/sim/`을 만든다. **TypeScript 구현의 1:1 번역이며 창의성을 발휘하지 않는다.**

> **포팅 방향은 TS → Python 이다.** `CLAUDE.md` §저장소 구조의
> "client/src/ sim/ ← server sim의 TypeScript 포팅" 서술과 방향이 반대였다.
> 실제 순서는 Phase 0(브라우저) → Phase 2(TS 정수화) → Phase 3(Python 번역)이다.
> `CLAUDE.md` 를 이에 맞춰 고쳤다.

```
server/src/talus/sim/
  intmath.py     [SIM] floor_div · isqrt · iabs · clamp_int · hash32 (numpy 벡터 + 스칼라)
  trig.py        [SIM] tables/trig.bin 조회. **파일은 호출자가 읽어 넣는다**
  terrain.py     [SIM] numpy 벡터화 자동자, carve/deposit, 연결성
  ballistics.py  [SIM] 탄도 적분, 피해 계산, 탱크 재배치
client/tools/gen-golden.mts      골든 리플레이 생성기 (TS 가 진실의 원본)
server/tests/test_cross_sim.py   교차 검증 (게이트 2)
server/tests/test_ballistics.py  탄도 이식 검증
```

- [x] numpy 벡터화 자동자 (`terrain.md` §3)
- [x] 골든 리플레이 포맷 (`docs/decisions.md` B2)과 `test_cross_sim`
- [x] 탄도 이식 (`trig.py`, `ballistics.py`). 평지 사거리가 TS 와 **같은 1,899 px** 다
- [ ] 초기 지형 생성기 (`docs/decisions.md` B1 — **명세가 미결이다**).
      그때까지 리플레이는 초기 격자를 `*.grid.gz` 사이드카로 싣는다.
      헤더의 `kind` 가 이 임시 조치를 표시한다
- [ ] 무기·턴 진행 (`weapons.py`, `match.py`). 탄도까지 담는 골든 리플레이도 여기서 나온다 —
      지금 리플레이는 지형 전용이라 `test_ballistics.py` 가 그 자리를 메우고 있다

> **`sim/` 은 파일을 읽지 않는다** (절대 규칙 1). `trig.py` 는 TS 쪽과 똑같이
> `load_trig(bytes)` 로 받기만 하고, 어디서 읽을지는 호출자가 정한다.
> 대신 적재 시점에 0°/45°/90°/180° 를 검증한다 — 스케일·엔디언·배열 순서가 어긋난
> 표는 전부 여기서 걸린다. 표가 조용히 틀리면 증상이 "가끔 안 맞음"이라 잡기 어렵다.

**완료 조건**
- [x] 골든 리플레이 20개가 Python·TS 양쪽에서 매 턴 동일 체크섬 — 20개 × 400스텝,
      21/21 통과. 표본 지점마다 체크섬과 질량을 함께 대조한다
- [x] 서버 자동자 1스텝이 3ms 미만 — **1.40 ms** (전 격자 활성) / **1.01 ms** (실전 폭발 1발).
      첫 구현은 9.04 ms 였고 활성 행 구간만 잘라 계산해 6.5배를 얻었다.
      §5.1 이 금지한 것은 *규칙 적용 대상*의 과대 포함이지 중간 계산 범위가 아니다
- [x] 리플레이 하나가 양쪽에서 1000턴을 돌아도 안 갈라진다 — `terrain-long1k` (1000턴)

> **장기 리플레이 두 개는 역할을 나눠 맡는다.** 둘 다 크게 만들면 검증 비용이 규칙 변경을
> 막는 수준이 된다 — 대형 폭발로 1000턴을 돌리면 300만 스텝이고 생성 34분 + 재생 57분이다.
> 자동자를 만질 때마다 1시간 반이 드는 게이트는 결국 아무도 안 돌리고, 그건 게이트가 없는 것과 같다.
>
> | | 턴 | 폭발 반경 | 무엇을 보는가 | 재생 |
> |---|---|---|---|---|
> | `terrain-long` | 60 | 14~59 (대형) | 한 턴의 **규모** — 대형 붕괴가 양쪽에서 같은가 | 약 3분, 상시 게이트 |
> | `terrain-long1k` | 1000 | 8~27 (중간) | **지속** — 누적 상태가 오래 가도 안 어긋나는가 | 약 12분, `-m slow` |

> **여기서 "턴"은 스텝이 아니다.** 한 턴은 `carve/deposit → 정착 → 연결성 재검사` 루프
> 전체다 (`terrain.md` §6.1). 스텝 단위 대조 20개가 전부 통과한 뒤에도 턴 단위 대조가
> 이탈을 잡아냈다 — 원인은 자동자가 아니라 골든 생성기였다. 생성기가 초기 정착을 마친
> 격자를 사이드카로 저장하면서 `step` 카운터는 리셋하지 않고 턴에 들어갔고,
> 그 카운터는 파일에 없다. 우선순위 해시가 `step` 을 먹으므로(§3.2) 재생 측은 같은
> 격자에서 다른 결과를 냈다. **사이드카에 담기지 않은 상태에 기록이 의존한 것**이고,
> 이건 스텝 단위 대조로는 영원히 안 잡힌다. 생성기가 로더와 같은 프롤로그를 밟도록 고쳤다.

**하지 않는 것**
WebSocket, 로비, DB. 아직 라이브러리로만 존재한다.

> 이 단계가 이 프로젝트에서 가장 지루하고 가장 중요하다.
> **여기서 대충 하면 Phase 4 이후 모든 버그가 "가끔 지형이 다르게 보임"으로 나타난다.**
> 그건 재현이 거의 불가능한 종류의 버그다.

## Phase 4 — 멀티플레이 (5~7일)

- FastAPI + WebSocket, msgpack
- 룸 수명주기, 턴 진행 (`netcode.md` §3)
- 리싱크, 재접속
- 간단한 로비 (코드 입장 방식. 매치메이킹은 나중)
- 체크섬 불일치 텔레메트리

**완료 조건**
- [ ] 서로 다른 4대의 기기에서 4인 매치가 끝까지 진행된다
- [ ] 100판 중 체크섬 불일치 0건
- [ ] 중간에 브라우저를 닫았다 열면 판에 복귀한다
- [ ] 조준 중 인터넷을 끊어도 판이 멈추지 않는다

**하지 않는 것**
랭킹, 계정, 결제, 매치메이킹 큐, EKS 배포.

## Phase 5 — 아트 (7~10일)

`docs/rendering.md`를 구현한다. **Phase 4까지는 프로토타입 그래픽으로 버틴다.**

- WebGL2 렌더러 전면 교체
- 지형 셰이딩 + 저각 조명 + 지층 노출/풍화
- 입자, 폭발 연출, 포스트 프로세싱
- HUD DOM 레이어
- 서체 확정

**완료 조건**
- [ ] 스크린샷 한 장으로 "이거 뭐야" 소리가 나온다
- [ ] 1920×1080에서 60fps
- [ ] 5라운드 진행 후 맵에 전투 흔적이 색으로 남아 있다
- [ ] `prefers-reduced-motion`이 동작한다

**아트를 마지막에 하는 이유:** 아트를 먼저 하면 재미없는 게임을 예쁘게 만드는 데 시간을 쓰게 되고,
게임이 재미없다는 사실을 알아차리는 시점이 늦어진다.

```
Phase 0  모래            ← 재밌는가?
Phase 1  손맛            ← 재밌는가?  (아니면 여기서 중단)
Phase 2  정수화·결정론
```
